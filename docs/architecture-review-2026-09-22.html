Problem
「一個 operation 從 scheduled → 觀察窗 → executed / abandoned / expired」沒有任何 module 擁有它。dynamicState 的 interface 幾乎和 implementation 一樣寬；兩個 builder 各抄一份 driver loop；查詢邏輯又在 operationScheduler。
Solution
一個 module 擁有 batch 陣列與所有 policy。builder 縮成 adapter，只回答「現在能不能插這個 template」，不碰 batch。
Wins
  • locality：重試 / 過期 bug 修一次（近期 commit 0154900、b4a8d8d、9c5ed63 都在這）
  • leverage：兩個 builder 只剩真正不同的部分
  • 測試：fsemBuilder_spec 停止 stub DynamicState.*（目前 34 處）
  • operationScheduler_spec 停止 self-stub 自己的 public 函式

Deletion test：刪掉 dynamicState 會讓約 10 個小迴圈散進三個 caller。複雜度重新出現，所以它有價值，但 policy 本體已經重複兩份。集中起來乾淨通過。

Problem
saveData 沒有 interface，它的 interface 就是整個形狀。「狀態 X 住哪裡」散在約 30 個呼叫點，任何改名都會波及 module、script、schema、UI。schema.lua 之所以是最熱檔案，就是這個症狀。
Solution
一個 module 負責 load、分發 slice、save。跨 feature 讀取變成具名查詢，不再走路徑。先只做 missileSystem 與 SIGINT 的 slice。
Wins
  • locality：「feature X 持久化什麼」一個檔案答完
  • leverage：24 個 script 縮成一個呼叫
  • 測試：load/save 合約可以測一次；目前是零
  • 解鎖 #4、#7

Deletion test：刪掉 saveData.lua，複雜度會以臨時 table 建構的形式在每個 module 重現。它是 load-bearing 的，但是以「資料 schema」的身分，不是 module。depth 不是放錯位置，是根本沒有。
