# 二、本專案設計 [專案設計]

## 1. 整體流程

```
開場：藍方近海佈雷（ScenEdit_AddMinefield）
航渡：母艦到乘載區，其他登陸艦艇到展開線
  → 獵雷艦（Type 082）反水雷，開水際通道與灘際通道（CMO 內建掃雷任務）
  → LST 到泛水出發線，釋放衝鋒舟
  → 衝鋒舟走水際通道，衝擊發起線轉橫隊，走灘際通道上岸
  → 衝鋒舟在岸上破障（障礙區方塊）
  → 灘際通道破障都完成，衝擊上陸：兩棲車泛水、分波登陸；氣墊船從母艦運送重裝備
  → 灘頭堡建立、絕對安全後，行政下卸（駁船搭橋、RORO 下卸大量戰甲車）
```

### Phase 對照（`constants.AMPHIBIOUS_PHASES`）

```
WAITING_ASSAULT → MINE_CLEARING → BOAT_ASSAULT → OBSTACLE_CLEARING → ASSAULT_LANDING → WAITING_ADMIN_OFFLOADING → COMPLETED
```

| Phase | 做什麼 | 換下一階段 | Code |
|---|---|---|---|
| `WAITING_ASSAULT` | 條件成立 → 算通道、派 082 | 派完 | `mineClearing.startMineClearing` |
| `MINE_CLEARING` | 082 走到最後航點（或被摧毀）→ `RTB()` | 全部完成 → 配對衝鋒舟、LST 前進（排除 082） | `mineClearing.updateMineClearing` |
| `BOAT_ASSAULT` | 072A/072III 進 `zone.landing.acv.area` 就放衝鋒舟 | 衝鋒舟全部到 S_lane 或被摧毀 | `assaultBoat.lua` |
| `OBSTACLE_CLEARING` | 計時 | 超過 `obstacle.clearSec` → 方塊標 `cleared` | `obstacleClearing.lua` |
| `ASSAULT_LANDING` | 衝擊上陸：兩棲車分波、氣墊船走通道 | 灘頭堡建立（暫用 `air.attackHelicopter.zone` 內 ZBD-05 ≥ 1，TODO） | `acvWave.lua`、`hovercraft.lua` |
| `WAITING_ADMIN_OFFLOADING` | 等絕對安全（TODO，目前直接放行） | `startAdminOffloading` 成功 | `adminOffloading.lua` |

兩棲車、氣墊船從 `ASSAULT_LANDING` 開始，之後的 phase（含 `COMPLETED`）也繼續跑。

`.scen` 參考點缺（`LANE_CENTER_*` 或 `OBSTACLE_*` 是空的）時，該區記 log、停在 `WAITING_ASSAULT`，不會 crash。

## 2. 艦艇位置與速度

| 位置 | 艦艇 |
|---|---|
| 登陸母艦乘載區（距岸 20–30 浬） | Type 075、076、071 |
| 登陸艦艇展開線（距岸 11–16 浬） | 其他登陸艦艇（072III、072A、073A、渡輪、駁船等） |

其他艦艇再往前到泛水出發線（距岸 2–4 浬），釋放衝鋒舟與兩棲車。`formation.deployLineSetbackNm = 13`（浬）是登陸艦艇展開線與登陸母艦乘載區的距離。

| 單位 | 速度 | 來源 |
|---|---|---|
| LST / LPD / 渡輪 / 駁船 | 14 kt | `formation.shipSpeed` |
| 兩棲車 | 8 kt（約 14.8 km/h） | 油門 Full |
| 氣墊船（Type 726A） | 40 kt | `formation.hovercraftSpeed`，設 `manualSpeed` |

## 3. 通道數量（依營數）

1 艘獵雷艦 = 1 個營 = 1 條水際通道 + 4 條灘際通道。

| 部隊規模 | 水際通道 | 灘際通道 |
|---|---|---|
| 4 個營 | 4 | 16 |
| 3 個營 | 3 | 12 |
| 1 個營 | 1 | 4 |

`config.red.amphibOps.zones[].fleet` 的 `type082` 數量需等於營數（目前 4 個作戰為 4 艘，2 個作戰為 1 艘）。

## 4. 反水雷（獵雷艦 Type 082，`PLATFORMS.TYPE_082`）

原文（第 16 頁）由掃雷艦、獵雷艦在編隊最前沿排雷並標示航道。

| 項目 | 設計 |
|---|---|
| 航行 | 展開線 → 泛水出發線，沿途開 1 條水際通道；再直線約 2 km 到衝擊發起線 |
| 灘際通道 | 到衝擊發起線後走弓字型，掃出 4 條，長度為衝擊發起線到岸（2–6 km） |
| 位置 | 水際通道延伸線在 4 條灘際通道正中間；偏移 -180、-60、+60、+180 m |
| 間距 | 灘際通道中心線相距 120 m（取圖 37 下限），弓字型轉折間距同為 120 m；相鄰獵雷艦水際通道相距 750 m（500 + 250） |
| 掃雷 | CMO 內建掃雷任務。**先設 `course`，再 assign 任務**。任務區域 4 角存在 `zoneState.minesweepers[guid].missionArea`；任務區域的設定是 `-- TODO`（使用者自己寫），詳見 [mineClearing](mineClearing.md) |
| 配對 | 082 依橫向位置排序，一艘配一條水際通道（左到右） |
| 完成 | 走到最後航點（距離 < `route.arrivalNm`）或被摧毀；通道存在 `zoneState.lanes` |
| 結束 | 呼叫 `unit:RTB()` |

與原文差異：灘際通道原由破障階段處理，改由獵雷艦開，因為衝鋒舟不能反水雷。

| 項目 | 設計 |

| 釋放 | 反水雷結束後，LST 到泛水出發線，各自位置釋放，先於兩棲車 |
| 路線 | 縱隊走水際通道，衝擊發起線轉橫隊，走灘際通道上岸 |
| 配對 | 1 條灘際通道 1 艘衝鋒舟，依橫向位置排序一對一 |
| 不足時 | 每艘 072A、072III 再釋放第二艘補 |

|---|---|---|---|
| type082 = 4（第一組） | 7 / 8 | 30 | 16，足夠 |
| type082 = 4（第二組） | 2 / 4 | 12 | 16，**缺 4 艘** |
| type082 = 1 | 2 / 3 | 10 | 4，足夠 |

第二組獵雷艦仍開滿 16 條，不派衝鋒舟的 4 條取橫向排序後同一側最外側，其餘 12 條連續一對一配對，航線最短。

## 6. 岸上破障（障礙區方塊）

CMO 沒有破障機制，改用「障礙區方塊」表示。

**障礙範圍**：玩家事先在 control panel 畫，一定畫在預定登陸點，用來阻止敵方裝甲車輛前進。灘際通道就是為了穿越這片障礙。不在 CMO 地圖上畫，方塊只存在 state 裡。

**方塊**：預設 50 m × 50 m，記 4 個頂點經緯度。鋪滿障礙範圍，數量由範圍大小決定。狀態有 `intact`（未破壞）、`clearing`（破障中）、`cleared`（已破壞），另記所屬灘際通道。

**流程**
1. 所有衝鋒舟都走完航線、停在登陸區後，開始計時。
2. 超過 `config.red.amphibOps.obstacle.clearSec`（預設值隨意給）後，衝鋒舟前方的方塊設為 `cleared`。
3. 一條灘際通道的方塊全部 `cleared`，該通道算完成。

**放行**：所有「有衝鋒舟破障的」灘際通道都完成，兩棲車才開始泛水，航線才能通過。沒有衝鋒舟的通道不計入，也不能走。第二組實際只能用 12 條。

**通過判斷**：航線（航點之間的線段）與方塊任一條邊相交（含相切）就算碰到。碰到的方塊都是 `cleared` 才放行，碰到任一 `intact` 就不放行。

## 7. 兩棲車泛水與分波

### 改版前（參考）

| 項目 | 改版前 |
|---|---|
| 觸發 | 事件腳本 `launchACV.lua`，每 5 分鐘對區內每艘船各觸發一次 |
| 可釋放的船 | 071、072III、072A、073A、渡輪（`isFerryOrLST`；舊版曾含掃雷艦） |
| 每次數量 | 每艘船 5 輛（寫死 `num = 5`），先 ZBD-05，用完才 ZTD-05 |
| 排列與航行 | 沿 `zone.heading` 排開，間距 0.05 浬；油門 Full，航線 `zone.landing.acv.destination` |
| 結束 | 艙內沒有 ZBD/ZTD（`count == 0`）就掛回基地並 RTB |
| 上限 | 無，有貨就一直放 |

### 可釋放車量

一個旅 = ZBD-05 112 + ZTD-05 112 = 224 輛。

| 船型 | 每艘載量（ZBD + ZTD） | 放完要幾次 |
|---|---|---|
| 072III / 072A | 5 + 5 | 2 |
| 073A | 3 + 3 | 2 |
| 渡輪 | 56 + 56 | 23（約 115 分鐘） |

| 區 | 非渡輪 | 渡輪 | 合計 | 約幾個旅 | 累計第 1 / 2 次 | 達 224 輛 |
|---|---|---|---|---|---|---|
| 桃園 | 192 | 448（4 艘） | **640** | 2.9 | 130 / 232 | 第 2 次（約 5 分鐘） |
| 喜樹 | 72 | 448（4 艘） | **520** | 2.3 | 60 / 112 | 第 8 次（約 35 分鐘） |
| 澎湖 | 56 | 0 | **56** | 0.25 | 30 / 56 | 不會達到 |

不控制的問題：桃園第 2 次就超過一個旅，旅級規模之後仍持續放出；ZBD 先放，可能先超過 112 輛。

### 分波設計

**規則**：每區同時存活的兩棲車不超過旅級規模（ZBD-05、ZTD-05 各 112，各自計算）。

1. 每區保存已放出的車輛 GUID，存活數 = 還活著的 GUID 數（航行途中也算）。被擊殺的車由 [trackedUnits](trackedUnits.md) 刪掉（擊殺事件，或第一次查不到時）。
2. 每次觸發先算剩餘額度（上限 − 存活數），同一個 tick 內多艘船共用，先處理的先拿。
3. 額度用完就暫停，各船留在泛水出發線，不 RTB。
4. 暫停後，符合任一條就補下一波，補到上限為止：
   - 戰損：存活數降到上限的 `(1 − lossRatio)` 以下。
   - 逾時：距離暫停超過 `holdSec`。
5. 逾時不能小於兩棲車到灘時間（泛水出發線距岸 2–4 浬，8 kt，約 15–30 分鐘）。

預計波次：桃園 3 波（224 / 224 / 192），喜樹 3 波（224 / 224 / 72），澎湖 1 波（56）。

**config**（`config.red.amphibOps.acvWave`；各區的 `capacity` 在 `zones[i].landing.acv.capacity`）：`lossRatio`（0.3）、`holdSec`（30 × 60）、`hovercraftWaitSec`（氣墊船等第一波的上限）。

**state**（`SBJ__ZoneState`）：`acvGuids`、`acvPausedAt`、`acvFirstWaveFull`、`acvWaitStartedAt`。機制與取捨見 [acvWave](acvWave.md)。

### 實作

- `ASSAULT_LANDING` 之前，`LandingOps.launchACV` 不動作。
- `AcvWave.release` 回傳 `{ count, isEmpty, isPaused }`：額度 0 → `isPaused`，船不 RTB；艙內沒 ZBD/ZTD → `isEmpty`，照舊掛回基地 RTB。
- 071 沒有 ZBD/ZTD，第一次觸發就 RTB（掃雷艦不算 `isFerryOrLST`）。
- `removeCargoByPriority` 依各車種額度分配（`min(5, 該車種額度)`）。
- 每輛車放出後立刻記 GUID，同 tick 後面的船自然拿到較少額度。
- 每輛車用 `routePlanner` 算自己的航線（走 `cleared` 灘際通道，停在自己的停車位）。沒有可用通道時退回 `zone.landing.acv.destination` 並記 WARN。

## 8. 佈雷

`MineClearing.createMinefields` 依 `config.red.amphibOps.minefields` 中屬於該區的每筆呼叫一次 `ScenEdit_AddMinefield`（藍方、`SEA_MINE`），`area` 是空的就跳過。目前**只有快轉模式會呼叫**（見 [debugFlow](debugFlow.md)），`LandingOps.init` 並不佈雷。灘岸雷區以後再做。
