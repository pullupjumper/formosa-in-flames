# Project Documentation

## Overview

This is a **Command: Modern Operations (CMO)** scenario scripting project written in **Lua**. The project appears to simulate a complex military scenario involving China, Taiwan, and US forces with sophisticated systems for:

- Air Tasking Orders (ATO)
- Strike Planning and Coordination
- Amphibious Operations
- Electronic Warfare (EW)
- Integrated Air Defense Systems (IADS)
- Unit Generation and Management
- Landing Operations

## Project Structure

### Core Modules (`src/core/`)
- `init.lua` - Main initialization script that sets up all game systems
- `constants.lua` - Configuration constants including platform DBIDs, base GUIDs, and operational areas
- `schema.lua` - Type definitions and data structures using LuaLS annotations
- `saveData.lua` - Save/load functionality for persistent game state
- `gKH_*.lua` - Game-specific integration modules

### Utility Modules (`src/utils/`)
- `gameApi.lua` - Wrapper for CMO game API functions with error handling
- `gameUtils.lua` - Higher-level game utility functions (positioning, missions, etc.)
- `utils.lua` - General utility functions (string manipulation, math, date parsing)
- `logger.lua` - Logging system that works both in-game and during development

### Feature Modules (`src/modules/`)
- `unitGenerator.lua` - Creates and manages military units with formation logic
- `attackManager.lua` - Handles combat and attack coordination
- `assignMission.lua` - Mission assignment and management
- `bearingOnlyLaunch.lua` - Specialized launch mechanics
- `launcher.lua` - Weapon launcher systems
- `runwayRepairment.lua` - Airfield damage and repair simulation
- `unitStatusUI.lua` - User interface for unit status

#### Strike Planning (`src/modules/strikePlanner/`)
- `airTaskingOrder.lua` - Air mission planning and coordination
- `fireSupportPlan.lua` - Artillery and fire support coordination
- `fireSupportTaskProcessor.lua` - Processing fire support tasks
- `recon.lua` - Reconnaissance operations
- `strikePackageProcessor.lua` - Strike mission coordination
- `targetingProcess.lua` - Target selection and prioritization

#### Electronic Warfare (`src/modules/EW/`)
- `commsJamming.lua` - Communications jamming systems
- `GPSJamming.lua` - GPS jamming operations
- `sigint.lua` - Signals intelligence gathering

#### Landing Operations (`src/modules/landingOps/`)
- `amphibiousAssault.lua` - Amphibious assault coordination
- `amphibiousLogistics.lua` - Logistics for amphibious operations
- `secondWaveUnloading.lua` - Follow-up wave management
- `shipMovement.lua` - Naval vessel movement and positioning

### Scripts (`src/scripts/`)
Organized by faction (china/, taiwan/, us/) and functionality, containing event handlers and automated behaviors.

### Tools (`tools/`)
- `clean_lua_scripts.py` - Python utility for processing Lua files (removes requires, cleans modules)

## Key Conventions and Best Practices

### Code Organization
- Use clear module separation with single responsibility principle
- Organize scripts by faction (China, Taiwan, US) in separate directories
- Group related functionality (EW, landing ops, strike planning) in subdirectories
- Keep utility functions separate from game logic

### Lua Coding Standards
- Use LuaLS type annotations extensively (`---@param`, `---@return`, `---@class`)
- Prefix custom types with project identifier (e.g., `SBJ__CONFIG`, `CMO__Unit`)
- Use descriptive function and variable names
- Include Chinese comments for complex military concepts
- Implement error handling with `Utils.safeCall()` wrapper

### Configuration Management
- Centralize all configuration in `src/core/constants.lua`
- Use structured configuration with nested tables (`.c`, `.t`, `.u`, `.s` namespaces)
- Define platform DBIDs and base GUIDs as constants
- Store operational areas as reference point arrays

### API Usage
- Wrap all CMO API calls in `src/utils/gameApi.lua` with error handling
- Use `Logger` module for consistent logging that works in-game and during development
- Implement retry logic for unit creation operations
- Validate API responses before proceeding

### Unit and Formation Management
- Use formation constants for consistent positioning (`FORMATION.ANGLES`, `FORMATION.DISTANCES`)
- Implement cleanup functions for existing units before creating new ones
- Use descriptive naming conventions for units and groups
- Support both manual and automated unit generation

### Error Handling
- Use `Utils.safeCall()` for critical operations
- Log errors with context information
- Implement fallback behaviors where possible
- Validate inputs before API calls

### Development Workflow
- Use `config.isDevMode` flag to enable development features
- Implement both in-game and console logging
- Use the Python cleaning tool for deployment preparation
- Test modules independently when possible
