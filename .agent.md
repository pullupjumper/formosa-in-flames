# Command: Modern Operations - China-Taiwan Conflict Scenario

## Project Overview

This is a comprehensive Lua-based scenario for Command: Modern Operations (CMO), a military simulation game. The project simulates a complex China-Taiwan conflict with sophisticated AI behaviors, multi-domain operations, and realistic military command structures.

### Key Information
- **Language**: Lua (Command Lua API)
- **Platform**: Command: Modern Operations
- **Scenario Type**: China-Taiwan military conflict simulation
- **Architecture**: Modular event-driven system
- **File Count**: 71 Lua files across multiple modules

## Project Structure

### Core System (`src/core/`)
- `init.lua` - Main initialization system for all scenario components
- `constants.lua` - Massive configuration file with platform IDs, operational areas, and military parameters
- `saveData.lua` - Persistent data structures for scenario state management
- `schema.lua` - Type definitions and API documentation for CMO integration
- `gKH_*.lua` - External libraries for contact notes and state management

### Modules (`src/modules/`)
- **Strike Planning**: Air tasking orders, targeting processes, fire support planning
- **Landing Operations**: Amphibious assault, logistics, ship movement coordination
- **Electronic Warfare**: GPS jamming, SIGINT collection, communications jamming
- **Unit Management**: Generation, status tracking, mission assignment
- **Weapons Systems**: Launcher management, bearing-only launches, attack coordination

### Event Scripts (`src/scripts/`)
- **China Operations**: Amphibious ops, IADS management, EW operations, unit generation
- **Taiwan Operations**: Defensive systems, launcher management, aircraft operations
- **US Operations**: SIGINT collection and support operations
- **Scoring System**: Mission objective tracking and ROE enforcement

### Utilities (`src/utils/`)
- `gameApi.lua` - Wrapper for CMO API with error handling and safety checks
- `gameUtils.lua` - Game-specific utilities (area creation, positioning, messaging)
- `utils.lua` - General utilities (math, string manipulation, coordinate calculations)
- `logger.lua` - Logging system with game/development mode detection

### Tools (`tools/`)
- `clean_lua_scripts.py` - Python script for processing Lua modules (removes requires, cleans exports)

## Development Guidelines

### Code Organization
- Use modular architecture with clear separation of concerns
- Follow the established `require()` pattern for module dependencies
- Maintain consistent naming conventions (camelCase for functions, UPPER_CASE for constants)
- Group related functionality in appropriate subdirectories

### Type Annotations
- Extensive use of LuaLS annotations (`---@class`, `---@param`, `---@return`)
- Custom type definitions prefixed with `SBJ__` (e.g., `SBJ__CONFIG`, `SBJ__SaveData`)
- CMO API types prefixed with `CMO__` (e.g., `CMO__Unit`, `CMO__Contact`)

### Configuration Management
- All platform DBIDs defined in `constants.lua` (CONFIG.platformDBID1-68)
- Operational areas defined using reference point arrays
- Weapon systems configured with default ammunition counts and thresholds
- Side-specific configurations separated (China: `c`, Taiwan: `t`, US: `u`)

### Error Handling
- Use `Utils.SafeCall()` for error-prone operations
- Implement null checks before accessing CMO API objects
- Provide meaningful error messages through the logging system
- Graceful degradation when units or systems are unavailable

### State Management
- Persistent state stored in `saveData` structure
- Use `gKH.State.SaveTableToKey()` and `gKH.State.LoadTableFromKey()` for persistence
- Initialize state only when necessary (check existing data first)
- Separate activation flags for different subsystems

### Military Simulation Best Practices
- Implement realistic OODA (Observe, Orient, Decide, Act) loops
- Use proper military terminology and unit designations
- Respect engagement rules and doctrine
- Model communication degradation and jamming effects
- Implement realistic reload and movement times

### Event-Driven Architecture
- Scripts triggered by specific game events (unit enters area, time-based, etc.)
- Use descriptive event names that indicate purpose and timing
- Implement proper cleanup for temporary events
- Consider performance impact of frequent event processing

### Testing and Debugging
- Use `CONFIG.isDevMode` flag for development-specific behavior
- Implement comprehensive logging for troubleshooting
- Test with different difficulty settings and scenarios
- Validate unit availability before operations

### Performance Considerations
- Minimize API calls in frequently executed scripts
- Cache unit references when possible
- Use efficient area-based filtering for large unit sets
- Implement proper cleanup for completed operations

### Documentation Standards
- Document all public functions with parameter and return types
- Include usage examples for complex systems
- Maintain clear comments explaining military doctrine and tactics
- Document configuration options and their effects
